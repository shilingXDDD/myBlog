# 1.AsyncTask(api30弃用)

## 使用
    - 概念 
  是一个用于轻量级异步操作的抽象类,主要是基于线程池和Handler（内部维护线程池用来执行后台任务/Handler用来切换回主线程更新UI）
    - 用法
  * **doInBackground(Params...params)**:在后台执行主要任务
    * onPreExecute():主线程中执行，表示任务开始前的准备工作
    * onPostExecute(Result result):主线程，任务完成之后的处理
    * onProgressUpdate(Progress...values):后台任务完成过程中更新进度

## 局限性
  * 任务执行时间过长会内存泄露（销毁时要调用cancel(true)终止任务）/上下文错配
  * 必须在UI线程中进行实例化和调用
  * 默认串行执行，需要显式调用executeOnExecutor(....)
## 线程池的使用
 * 默认五个，还可自定义
## 与其他异步任务的比较
 * 相比于Thread + Handler更加简便，但他没有IntentService那么稳健
 * RxJava和Kotlin Coroutine更强大，逐渐替代了AsyncTask成为主流

## **替代方案**
  1. UI相关的异步任务
  - Kotlin协程(生命) + LifeCycle(Lifecycle/viewModelScope)
     * viewModelScope启动协程，viewModel销毁，协程会自动取消，彻底解决AsyncTask带来的内存泄露和屏幕旋转导致的崩溃问题
     * 协程可以用try-catch优雅捕获异常，AsyncTask的doInBackground如果不手动处理，会导致闪退且难以追查
  - Java项目备选：ExecutorService/ThreadPoolExecutor
  2. 需要保证执行的后台任务
  - WorkManager
  3. 极简的短时后台计算
  - Executors

## 如何迁移AsyncTask老代码
**先看AsyncTask的泛型**
  1. 纯计算 -> 直接替换为Executors
  2. 更新UI + Kotlin项目 -> 内部逻辑抽出来，用viewModelScope.launch(Dispatchers.IO)包起来，结果更新写在主线程作用域里
  3. 更新UI + Java项目 -> 用ExecutorService执行，再通过Handler或runOnUiThread更新UI，如果有取消逻辑(isCancel()),需要在替换时加上Future.cancel()或Job.cancel()

# 2. Android中进程/线程的区别

## 先回顾下Java的进程和线程

 - 进程：是由JVM管理的内存区域（堆、栈、方法区），主要是用于实现区域隔离 **资源分配的基本单位**
 - 线程：是JVM调度的基本单位，最终会映射到操作系统的原生线程上；但在java层面所看到的是java.lang.Thread,受JVM线程模型调度  **CPU调度的基本单位**
 - 区别：
    * 资源占用：进程独立，线程共享；进程隔离性强，线程隔离性弱；进程创建/销毁开销大，线程创建/销毁开销小（只保留少量的寄存器指针和栈指南） -> 线程池
    * 通信方式：进程间通信（IPC）要借助管道、消息队列、Socket、信号量、共享内存等（在安卓上最核心的是Binder）,线程间通信只需要一个全局变量（但要配合volatile/synchronized/Lock/ wait/notify 来保证线程的安全性和可见性）
    * 调度和并发：多核CPU的不同进程可以并行运行在不同核心的CPU上；线程抢占式调度，同个进程的多个线程也可以被调度到不同的CPU核心上并行执行

## Android的进程和线程

 - Android的底层是Linux，Android的进程本质上就是一个Linux进程，拥有独立的PID和进程空间
 - Android的线程本质上就是Linux的轻量级线程，底层通过clone()进行调用创建
 - IPC:Binder是核心，还有ContentProvider、Messenger、以及AIDL(Android Interface Definition Language)

# onTouch和OnTouchEvent

## 核心区别

- onTouch:onTouchListener接口定义的方法，是外部提供给View的监听器回调
- onTouchEvent:View自身处理触摸事件的方法

## 详细对比

1. 所属层面和接口：
* onTouch:View自带的成员方法，可以被重写
* onTouchEvent:View.onTouchListener接口的接口方法，是开发者通过setOnTouchListener注入的外部回调
2. 返回值含义：
* onTouch:返回 true 表示监听器消耗了该事件，此时 onTouchEvent 将不会被调用；返回 false 表示不消耗，事件继续传递给 onTouchEvent
* onTouchEvent:false表示当前View不消耗该事件，true表示已消耗，后续的ACTION_MOVE\ACTION_UP还会传入给它
3. 优先级：
   onTouch 的优先级 高于 onTouchEvent。因为 View 在分发事件时，会先检查有没有设置 OnTouchListener

## 触发顺序

dispatchTouchEvent()
-> onTouchListener.onTouch()
-> onTouchEvent()

```
// View 类的 dispatchTouchEvent 源码简写逻辑
public boolean dispatchTouchEvent(MotionEvent event) {
    boolean result = false;
    
    // 1. 先检查有没有设置 OnTouchListener
    if (mOnTouchListener != null && mOnTouchListener.onTouch(this, event)) {
        // 如果 onTouch 返回 true，说明外部处理了，直接返回，不再往下走
        result = true;
    } else {
        // 2. 如果 onTouch 返回 false（或没设置），或者当前不是按压动作，调用自身的 onTouchEvent
        result = onTouchEvent(event);
    }
    
    return result;
}
```
